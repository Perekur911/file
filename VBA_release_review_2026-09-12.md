## 1. CVD: исправить заполнение заданий в PowerQuery

**Обязательно, если код ещё такой, как в архиве.**

Файл: `addin_source/modules/PowerQuery.bas`.

Процедура: `Refresh_Project`.

Найти ветку:

```vb
ElseIf taskType = "CVD" Then
```

После:

```vb
emptyCVDPage = FindEmptyFormCVD()
```

вставить:

```vb
Dim cvdTaskRange As Range
Dim cvdSampleRange As Range

Set cvdTaskRange = GetCVDFormRange(emptyCVDPage, "TaskId")
Set cvdSampleRange = GetCVDFormRange(emptyCVDPage, "sampleCode")

If cvdTaskRange Is Nothing Or cvdSampleRange Is Nothing Then
    Err.Raise vbObjectError + 4400, "Refresh_Project", _
              "Не удалось вычислить поля выбранной формы CVD."
End If
```

В этой же ветке заменить только две строки `With`:

```vb
With CVD_list.Range("CVD_" & emptyCVDPage & "_TaskId").MergeArea
```

на:

```vb
With cvdTaskRange.MergeArea
```

и:

```vb
With CVD_list.Range("CVD_" & emptyCVDPage & "_sampleCode").MergeArea
```

на:

```vb
With cvdSampleRange.MergeArea
```

Всё содержимое блоков `With ... End With` оставить: запись значения, оформление и `Locked`.

Причина: при `emptyCVDPage = 2` старый код ищет физические имена `CVD_2_TaskId` и `CVD_2_sampleCode`. Их больше не должно быть. Изменение только самого модуля CVD эту внешнюю ветку не исправляет.

Поиск задания через `CVD_list.Range("CVD_1_TaskId").EntireRow.Find(...)` не требует имени второй формы; его можно оставить. Для максимальной точности поиска в будущем можно обходить только вычисленные ячейки TaskId, но это отдельное улучшение.

## 2. Stable: добавить снятие защиты при обновлении проекта

**Обязательно, если Stable ещё не добавлен в эти два списка.**

Файл: `addin_source/modules/wrappers.bas`.

Процедуры:

- `Refresh_Project_wrap`;
- `silentRefresh_Project_wrap`.

В каждой процедуре найти последний аргумент `CallMacroEx` — список исследований. В архиве он заканчивается так:

```vb
"AP", "OP", "OPOH", "BP", "GC", "GOR", "SSF", "EMV", "JOIN", "CCE", "Rec", "CVD", "DLSepTest"
```

Заменить эту строку на:

```vb
"AP", "OP", "OPOH", "BP", "GC", "GOR", "SSF", "EMV", "JOIN", "CCE", "Rec", "CVD", "DLSepTest", "STABLE"
```

Остальные строки процедуры не менять.

Причина: `Refresh_Project` уже записывает TaskId и sampleCode на Stable и меняет `Locked`. `CallMacroCore` снимает защиту только для исследований, переданных в списке. Без Stable эти действия могут завершиться ошибкой на защищённом листе. Исправление служебных листов в `EndMacro` не заменяет эту правку.

`DLSepTest` здесь допустим: это реальное имя листа. Можно использовать вместо него `DLST`, если оставлена существующая обработка `GetStudySheetPrefix`.

## 3. Общая валидация: исправить IsValidExecutor

**Найдена логическая ошибка в доступной версии. Она затрагивает не только новые исследования.**

Файл: `addin_source/modules/helpersForm.bas`.

Функция: `IsValidExecutor`.

Найти внутри цикла:

```vb
If IsError(Application.Match(values(i), executors, 0)) Then
    IsValidExecutor = False
End If
```

Заменить на:

```vb
If IsError(Application.Match(values(i), executors, 0)) Then
    IsValidExecutor = False
    Exit Function
End If
```

Причина: без `Exit Function` неизвестный исполнитель получает `False`, но затем функция доходит до последней строки `IsValidExecutor = True` и возвращает успех. Эту функцию вызывают валидаторы Stable, DLST, последний CVD и другие исследования.

Проверка в Immediate Window после компиляции:

```vb
? IsValidExecutor("MR")
? IsValidExecutor("НЕИЗВЕСТНЫЙ")
? IsValidExecutor("MR,НЕИЗВЕСТНЫЙ")
```

Ожидается соответственно `True`, `False`, `False`.

Отдельно: если разрешены записи вроде `MR, AA`, нужно нормализовать каждый элемент через `Trim$`. Сейчас исходный код не удаляет пробел после разделителя. Это выбор формата ввода, а не та же ошибка возврата результата.

## 4. Stable: не переименовывать ссылки внутри скопированных формул

**Риск при переходе на имена только первой формы; наличие ошибочных формул без актуального шаблона не подтверждено.**

Файл: `addin_source/modules/Stable.bas`.

Процедура: `ResetStableCopiedForm`.

Сейчас она вызывает общую `ResetCopiedCell`, определённую в `Rec.bas`. Та для обычной формулы выполняет текстовую замену `"_" & oldFormNumber` на `"_" & newFormNumber`.

Если формула содержит базовое имя `Stable_1_*`, добавление второй формы может превратить его в несуществующее `Stable_2_*`. Кроме того, эта замена не ограничена полными именами диапазонов.

Для модели «имена только первой формы» в Stable лучше сохранять скопированные формулы без такого переименования и очищать только константы.

В `ResetStableCopiedForm` заменить вызов:

```vb
ResetCopiedCell _
    newRange, _
    oldFormNumber, _
    newFormNumber
```

на:

```vb
Stable_ClearNonFormulaCells newRange
```

В тот же стандартный модуль Stable, вне остальных процедур, добавить:

```vb
Private Sub Stable_ClearNonFormulaCells(ByVal targetRange As Range)

    If targetRange Is Nothing Then Exit Sub

    Dim cell As Range
    Dim area As Range

    For Each cell In targetRange.Cells

        If cell.MergeCells Then
            Set area = cell.MergeArea
            If Not RangeHasFormula(area) Then
                area.ClearContents
            End If
        ElseIf Not cell.HasFormula Then
            cell.ClearContents
        End If

    Next cell

End Sub
```

`oldFormNumber` можно пока оставить в сигнатуре `ResetStableCopiedForm`: неиспользуемый параметр не мешает работе. Не менять общую `ResetCopiedCell` в Rec ради Stable — её продолжают использовать другие модули.

Важное ограничение: простое сохранение формулы не делает ссылку `Stable_1_*` относительной. Если формулы шаблона действительно читают именованные поля первой формы, их нужно отдельно изменить на ссылки на ячейки своей формы или другую согласованную относительную схему. При обычных относительных адресах Excel сам сдвигает ссылки во время копирования.

## 5. Ранее обсуждённые исправления: сверить, не вносить повторно

### DLST: добавление и удаление

В архивном `DLST.bas` `AddFormDLST` и `DeleteLastFormDLST` ещё заглушки. Ты уже получил код их замены; без свежего экспорта факт вставки не проверить.

Проверить, что в актуальном модуле:

- действительно копируется/удаляется блок из 18 столбцов;
- первая базовая форма не удаляется;
- номер страницы записывается в рассчитанную ячейку;
- при копировании очищаются поля-константы, в том числе ID, а формулы сохраняются;
- имена `DLST_2_*` и последующие не создаются.

Отдельная функциональная граница: в архивной версии `FindEmptyFormDLST` возвращает `0`, когда свободных заранее подготовленных страниц нет; загрузка `sequential` не добавляет недостающие страницы. Вставка только Add/Delete этого поведения не меняет. Если нужен автоматический рост при обновлении заданий или загрузке из БД, надо дополнительно связать эти ветки с `AddFormDLST` и проверять, что число форм действительно увеличилось. Если страницы создаются вручную кнопкой заранее, это ограничение можно оставить.

### Защита служебных листов

Ты сообщил, что уже исправил защиту. Сверить наличие `Task_mix` и правильного `ProjectLIF` в `EndMacro`. В старом архиве ещё остался `Project_LIF`.

### Тип задания Stable

Согласованный код исследования для синхронизации — `STABLE`. При этом архивная `SetTaskStatusOnly` уже выполняет `UCase$(Trim$(taskType))`; одна только разница `Stable`/`STABLE` на её входе не доказывает создание разных цепочек статуса. Предыдущее утверждение о такой неизбежной ошибке было слишком категоричным.

Нормализация типа в `PowerQuery.Refresh_Project` — отдельный вопрос: там сравнение с `"Stable"`. Если в Excel-таблице Task приходит `STABLE`, эта ветка при обычном двоичном сравнении не сработает. Проверить реальное значение из таблицы Task; не заменять его наугад без учёта остальных типов заданий.

Новые обязательные MsgBox не предлагаются: при необходимости использовать существующие уведомления/журнал. Твоё решение не добавлять блокирующие окна учтено.

## 6. Финальная проверка на тестовой среде

Все сценарии выполнять на копии формы и тестовой БД, с корректными путями тестового окружения. Копия Excel сама по себе не меняет путь БД в Python!

1. В целевом Excel открыть VBE: `Alt+F11 → Debug → Compile VBAProject`. Проверить отсутствие `MISSING` в `Tools → References`.
2. Обновить проект с заданиями Stable, DLST и CVD. Для CVD заполнить минимум вторую форму без каких-либо `CVD_2_*` имён.
3. Для каждого из трёх исследований добавить страницу. Проверить пустые ID/вводимые поля, сохранность формул и правильный номер страницы.
4. В новой форме изменить входные значения: результаты её формул должны зависеть от неё, а не от первой формы. Для Stable проверить независимость нового checkbox `pressureAbs`.
5. Сохранить новые данные, проверить выдачу настоящих ID вместо временных ключей. Для CVD/DLST проверить родительские и дочерние строки.
6. Изменить одно поле, сохранить снова: должна обновиться существующая запись, а не появиться дубль. Сверить `sampleCode + analyseNumber`.
7. Выполнить Load: вернуть те же данные из БД, включая вторую форму и `last` у исследований со ступенями.
8. Проверить общий Save/Load/Validate, валидацию неверного исполнителя и отмену задания.
9. Удалить только специально созданную несохранённую пустую последнюю страницу. Проверить, что базовые имена первой формы целы. Удаление страницы не означает удаление соответствующего результата из БД.
10. На тестовой копии вызвать ошибку, например временно переименовать нужный лист. После выхода должны восстановиться события/перерисовка Excel и защита листов. Отдельно проверить Stable Add: в архивной процедуре нет локального восстановления `CopyObjectsWithCells` при ошибке во время копирования.
11. Проверить закрытие/повторное открытие формы и отображение состояний синхронизации.
